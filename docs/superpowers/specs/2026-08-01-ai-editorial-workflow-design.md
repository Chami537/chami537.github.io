# AI 编辑闭环设计

## 目标

把现有管理面板中的 AI 从一组孤立按钮升级为可反复使用的编辑闭环。用户应当能看清候选改了什么、用自然语言继续调整候选，并把 Dashboard 巡检发现的问题直接带到对应编辑器处理。

本期衡量价值的标准不是新增多少生成能力，而是减少从“发现问题”到“得到可保存修改”之间的重复操作。

## 设计原则

- AI 只生成候选，任何内容都不会自动保存、提交、构建或部署。
- 后续反馈只修改当前候选，不把用户已经拒绝的版本重新写回表单。
- 原文、候选和修改范围必须可辨认，避免盲目整段替换。
- 巡检项必须基于现有内容中的明确证据，不推断图片画面、季节、地点关系或作者意图。
- 密码文章、加密正文和 API 密钥继续遵守现有安全边界。
- 不加入“一键写整篇文章”、后台批量自动修复、向量库或对话历史持久化。

## 功能范围

### 1. 候选迭代

现有随笔、About、Work 和照片故事 AI 结果区增加“继续调整”入口。用户可输入一条短反馈，例如：

- 更短一点
- 保留第二句
- 不要升华
- 只改语病

服务端收到原文、当前候选、反馈、原任务和对应内容上下文，生成新的候选。迭代只保留在当前浏览器会话中，每次请求使用当前候选作为上一版，不保存完整对话历史。

反馈最多 500 个字符；原文和候选继续受现有输入长度限制。模型必须遵守原任务约束，例如照片故事仍不得补写未提供的画面细节，Work 仍保持事实型卡片文案。

用户可继续迭代，也可应用任意当前候选。应用后仅更新表单和脏状态，仍需手动保存。

### 2. 原文与候选差异

所有会替换文本的结果统一显示为差异视图，而不是只展示完整候选。

差异按词语和标点进行只读对照：删除内容、增加内容和未变化上下文使用不同样式。界面同时保留“查看候选全文”，避免较大改写在碎片化 diff 中难以阅读。

差异计算完全在前端进行，不把正文再次发送给第三方。渲染使用文本节点，不接受模型 HTML。输入过长或差异算法无法稳定处理时，安全降级为原文与候选并排显示。

标题、标签、检查问题等非替换型结果继续使用现有专用展示，不强行套用文本差异。

### 3. Dashboard 巡检修复队列

Dashboard 的确定性巡检和 AI 公开内容巡检统一输出可审阅队列。每项包含：

- 问题类型和明确说明
- 内容类型及内容标识
- 可定位的字段
- 来源：规则巡检或 AI 巡检
- “去处理”动作
- 适用时的“生成修复候选”动作

“去处理”切换到对应管理面板标签并打开目标记录，聚焦具体字段。路由与编辑器之间使用稳定的内容类型、标识和字段映射，不依赖问题文案解析。

“生成修复候选”只对有明确原文的文本字段开放。它复用对应业务域已有的 AI 约束和文风画像，结果进入同一差异与迭代界面。无法安全自动生成候选的问题只提供定位和人工说明。

队列不写入新的持久化状态。本期不实现已处理、忽略、批量应用或跨会话任务管理；刷新后由巡检重新计算当前问题，避免维护一套与内容状态脱节的任务数据库。

## 架构与模块边界

### 后端

现有 AI 路由增加受白名单约束的 `refine` 能力。请求携带业务域、原任务、原文、当前候选、用户反馈及已有上下文。服务端负责：

- 校验业务域、原任务、长度和字段类型
- 选择现有任务约束与文风画像
- 将原文、候选和反馈作为不可信数据封装
- 校验返回结果仍符合原业务域的数据结构
- 继续隐藏上游响应、提示词、正文和密钥

巡检接口补充稳定的定位元数据和候选能力标记，不让前端根据中文说明猜测目标编辑器。规则巡检保持确定性；AI 巡检继续排除密码文章与加密正文。

### 前端

AI 通用模块承担候选会话、反馈请求和差异展示；各业务域模块只提供以下适配信息：

- 如何读取当前原文及上下文
- 如何应用候选到表单
- 使用哪个任务约束
- 当前记录是否仍与请求快照一致

Dashboard 模块负责渲染队列和派发定位事件。各编辑器通过已有标签切换与编辑入口处理定位，并将目标字段交给 AI 通用模块。业务模块之间不直接读取彼此的 DOM。

## 数据流

### 继续调整候选

1. 用户对原文执行现有 AI 操作。
2. 前端保存原文快照、当前候选、任务和内容标识。
3. 用户输入反馈并请求继续调整。
4. 后端结合既有任务约束和已确认文风生成新版候选。
5. 前端确认记录与原文快照未变化后显示差异。
6. 用户继续反馈或应用候选；应用只修改表单。

### 从巡检进入修复

1. Dashboard 获得带定位元数据的巡检项。
2. 用户点击“去处理”或“生成修复候选”。
3. 前端打开对应业务标签、记录和字段。
4. 需要候选时，业务适配器读取当前字段并发起受约束的 AI 请求。
5. 结果进入统一差异与迭代界面。
6. 用户应用并手动保存，刷新巡检后问题自然消失或继续存在。

## 并发与错误处理

- 同一候选会话的新请求取消上一请求，旧响应不得覆盖新结果。
- 请求期间原文、候选或记录发生变化时，结果仍可查看，但禁止直接应用，并提示重新生成。
- 切换文章或业务记录时清空当前候选会话，避免跨内容误应用。
- DeepSeek 超时、限流、余额或格式错误只影响本次候选，原表单和现有巡检结果保持不变。
- 无法定位的过期巡检项提示刷新巡检，不静默打开错误记录。
- 差异渲染异常时降级为纯文本对照，不能阻断候选应用前的人工审阅。
- 不自动重试 AI 请求，避免重复计费。

## 测试

### 后端

- `refine` 仅接受允许的业务域和原任务。
- 反馈、原文、候选和上下文长度及类型校验完整。
- 各业务域约束在迭代中仍生效，尤其是照片事实边界和 Work 卡片长度。
- 密码文章、加密正文和敏感字段不能进入请求。
- 巡检结果返回稳定定位元数据，不暴露正文或内部路径。
- 上游超时、HTTP 错误和非法结构继续返回安全错误。

### 前端

- 差异视图正确显示新增、删除和未变化内容，并安全转义文本。
- 超长或异常输入能降级为并排纯文本。
- 用户可连续反馈，且每次基于当前候选继续调整。
- 原文或记录变化后禁止应用旧候选。
- Dashboard 队列可定位 About、Work、随笔和照片故事的目标字段。
- 只有支持安全候选的巡检项显示生成动作。
- 应用候选只修改表单并标脏，不调用保存 API。

### 回归门

- 完整 `pytest`
- 所有改动 JavaScript 的 `node --check`
- 强制 Chromium 管理面板冒烟
- `python manage.py build`

## 验收标准

- 用户可对当前 AI 候选连续提出自然语言修改要求。
- 所有替换型候选都能看见与原文的差异或安全降级对照。
- Dashboard 巡检项能准确跳转到对应记录和字段。
- 适合自动建议的问题可直接生成候选，并进入同一人工审阅流程。
- AI 不自动保存、不批量修改、不生成无证据事实。
- 密码内容、加密正文和 API 密钥安全边界不退化。
- 完整测试、构建和浏览器冒烟通过。
