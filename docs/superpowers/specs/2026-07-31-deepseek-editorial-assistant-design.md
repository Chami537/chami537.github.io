# DeepSeek 随笔编辑副驾驶设计

## 目标

在现有管理面板的随笔正文编辑器中加入 DeepSeek 编辑副驾驶，提供四项能力：

1. 生成摘要
2. 推荐结构化标签
3. 润色当前选区或全文
4. 检查文字、结构、Markdown 和链接问题

AI 只生成建议。用户必须查看结果并点击“应用”，AI 不直接保存文章、不改文件、不执行 Git，也不触发构建或部署。

## 范围

### 本期包含

- DeepSeek `deepseek-chat` 模型接入
- 服务端 API 密钥和请求代理
- 随笔正文编辑器中的 AI 操作区
- 四类结构化结果与人工应用流程
- 请求校验、超时、上游错误收敛和测试
- 密码保护文章默认禁止发送给第三方模型

### 本期不包含

- 对话式聊天、流式输出和多轮历史
- 向量数据库、RAG 和全站知识库
- 图片理解、照片说明和批量处理
- 自动保存、自动提交或自动部署
- 模型供应商抽象层和运行时供应商切换

只接入一个供应商和一个模型可保持实现直接；若以后确实增加第二个供应商，再提取统一接口。

## 架构

### 后端服务

新增 `backend/ai_service.py`，职责仅限：

- 从 `DEEPSEEK_API_KEY` 读取密钥
- 调用 `https://api.deepseek.com/chat/completions`
- 固定使用 `deepseek-chat`
- 请求 `response_format={"type": "json_object"}`
- 为四种任务构造系统提示和预期 JSON 结构
- 解析并验证 DeepSeek 返回值
- 根据 slug 在服务端拒绝密码保护文章
- 将网络、超时、鉴权、余额、限流及格式错误转换为不泄露上游响应和密钥的领域错误

使用 Python 标准库 `urllib.request`，不增加 SDK 依赖。默认超时 30 秒，单次输入最多 20,000 个字符，输出上限 1,500 tokens。正文按“不可信内容”包裹，系统提示明确禁止执行正文中的指令。

### Flask 路由

新增 `backend/routes/ai.py` 并注册 Blueprint：

`POST /api/ai/essay-assist`

请求：

```json
{
  "slug": "essay-12345678",
  "task": "summary | tags | polish | review",
  "content": "Markdown 或选中文本",
  "title": "可选标题",
  "existing_tags": ["可选", "标签"]
}
```

成功响应：

```json
{
  "task": "summary",
  "result": {
    "excerpt": "..."
  },
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 0
  }
}
```

各任务结果：

- `summary`：`{"excerpt": "..."}`，摘要不超过 160 个中文字符
- `tags`：`{"tags": ["主类", "主题", "类型"]}`，遵循现有主类/技术主题/内容类型顺序
- `polish`：`{"content": "..."}`，保留 Markdown 结构和事实
- `review`：`{"issues": [{"type": "...", "message": "...", "suggestion": "..."}]}`

路由复用现有全局 `/api/*` 登录守卫和状态请求 CSRF 检查，并使用 `require_json`。错误状态：

- `400`：请求形状、slug、任务、类型、空内容或长度不合法
- `403`：对应文章受密码保护
- `503`：未配置密钥、上游不可用、超时、限流或返回格式不合法

响应只提供可操作的中文错误，不返回 DeepSeek 响应正文、请求提示或密钥。

## 管理面板

新增 `assets/js/admin-ai.js`，在 `admin-api.js`、通用 UI 和随笔编辑模块之后加载。它负责：

- 读取当前 slug、正文、选区、标题和已有标签
- 调用 `/api/ai/essay-assist`
- 请求期间禁用操作按钮并显示状态
- 将结果渲染为纯文本，不使用模型返回的 HTML
- 将明确选择的结果应用到表单，但不保存

正文编辑器新增紧凑 AI 卡片，包含四个按钮和一个结果区：

- “生成摘要”：显示摘要；“应用到摘要”打开对应元数据表单并填入摘要
- “推荐标签”：显示标签；“应用到标签”调用现有 `renderEssayTaxonomy`
- “润色”：优先处理当前选区；无选区时处理全文；应用时只替换原处理范围
- “检查问题”：显示问题列表，不提供批量自动修改

应用内容后调用现有脏状态机制，保留当前手动保存流程。每次只保留最新请求结果，避免旧响应覆盖新编辑内容。

密码保护文章通过现有 `_essayAllData[].password_set` 在前端禁用，同时由后端根据请求 slug 和密码存储再次判定。此类文章不向 DeepSeek 发送正文，本期不提供绕过开关。

## 安全与隐私

- API 密钥仅存在于被 `.gitignore` 排除的本地 `.env` 或进程环境
- 前端、响应、日志、测试夹具和错误信息中均不出现密钥
- 不记录请求正文和 DeepSeek 原始响应
- 禁止密码文章调用 AI
- 不给模型任何工具、文件、网络、Git 或保存能力
- 使用严格任务白名单、输入类型校验和长度上限
- 模型输出只通过 `textContent` 或等价转义方式渲染
- DeepSeek 返回的 JSON 仍需在服务端按任务结构验证

## 错误与并发

- 前端使用 `AbortController` 取消同一编辑器的上一请求
- 请求失败时保留原正文和元数据，只显示错误提示
- 应用润色前确认编辑器内容和原选区仍与发起请求时一致；若已变化，拒绝自动替换
- DeepSeek 空响应、Markdown 代码围栏包裹的 JSON、非法 JSON 和字段缺失均由服务端显式处理
- 不自动重试，防止用户一次点击产生重复费用

## 测试

### 后端

- 未配置密钥时返回安全错误
- 四种任务构造正确的模型请求和结果结构
- `Authorization` 只发给 DeepSeek，不出现在返回值或异常文本
- 拒绝未知任务、非字符串内容、空内容、超长内容和非法标签上下文
- 正确处理超时、HTTP 错误、非法 JSON、空 choices 和任务字段缺失
- 路由在非测试模式下仍要求登录

外部 HTTP 调用使用依赖注入或 `urlopen` 替身测试，CI 不访问真实 DeepSeek。

### 前端与契约

- `admin-ai.js` 加载顺序正确，导出预期入口
- AI 卡片和四个按钮存在
- 结果使用纯文本渲染
- 应用摘要、标签和润色只修改表单，不触发保存 API
- 密码保护文章禁用 AI
- 浏览器冒烟测试使用本地路由替身，不消耗真实 API

### 回归

- 完整 pytest
- `node --check assets/js/admin-ai.js`
- `python manage.py build`
- 管理面板浏览器冒烟
- `git diff --check`

## 配置

本地 `.env`：

```dotenv
DEEPSEEK_API_KEY=your-key-here
```

可选配置暂不暴露；基础地址、模型、超时和限制作为服务端常量，避免无实际使用者的配置膨胀。密钥轮换只需修改本地环境并重启管理后端。

## 验收标准

- 登录后的随笔正文编辑器可使用四项 AI 能力
- AI 结果必须人工应用，且应用后仍需人工保存
- 密码保护文章不会向 DeepSeek 发送内容
- DeepSeek 不可用时原有管理面板和随笔编辑不受影响
- 密钥不出现在 Git 历史、浏览器网络响应或日志中
- 全部自动化测试和静态构建通过
