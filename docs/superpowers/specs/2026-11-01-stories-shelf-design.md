# 「留下来的故事」个人精选书架设计

日期：2026-11-01  
状态：按用户反馈调整中；以下最新展示调整为当前行为，原始设计与首次实施记录仅作历史参考。

## 当前方案 A：封面画廊（2026-11-01，优先于下方历史调整）

用户选择封面在上、感想在下的画廊方案。桌面三列、手机两列，桌面海报约 180–220px 宽；完整显示封面，作品名与最多两行的首段感想位于下方，保留宋体和混排。

点击作品后，在所在行下方插入独占一行的阅读区（正文最大宽 620px，透明背景、顶部细分隔线，按自然段排版；选中状态只用标题下划线标记），展示完整原文、辅助元数据与可公开访问的关联随笔。一次展开一部，再次点击同一部或点击「收起感想」关闭；关闭按钮把焦点还给原作品。键盘 Enter / Space 可操作，展开状态通过 aria-expanded / aria-controls 表达。屏幕跨列数变化时重新定位阅读区。展开以约 320ms 的高度与透明度过渡呈现，收起约 220ms；切换或连续点击时取消前一段动效并从当前状态接续，结束后恢复自适应高度，尊重系统减少动态效果偏好。

保留所有作品和后台排序，不添加分类栏、独立归档或「查看全部」，不修改用户内容源。按用户反馈移除公开展示中的「最喜欢」五角星，后台原有标记数据保留。

## 前次单列排版试用（历史）

改为单列文字优先排版，阅读宽度不超过 760px。海报在右侧作为点缀，桌面宽 64px、手机宽 48px；推荐语可随海报结束恢复完整行宽。保留宋体与作品混排，不增加独立页面或「查看全部」。

默认展示推荐语首段，首段超过 140 个字符时截取并加省略号；存在后续文字时提供「展开感想／收起感想」按钮，原地显示用户完整原文，不自动改写摘要。按钮支持键盘与 aria-expanded / aria-controls。短推荐语直接完整展示，不出现展开按钮。

「最喜欢」缩成标题旁的小星标，类型、作者、评分、日期合并成下方辅助信息。内容源、录入和排序规则不变。

## 前次展示调整（历史）

根据用户对实际预览的反馈，公开展示改为左侧小海报、右侧作品信息与推荐语：桌面海报宽 112px，手机宽 88px，保持 2:3 并完整展示图片。桌面两列、窄屏一列，避免海报占满大块页面。

移除主页「查看全部」入口，故事栏目及书架内容统一采用宋体字体栈（Noto Serif SC / Songti SC / STSong / SimSun）。其他主页栏目与管理面板字体保持现状。所有录入的作品按后台顺序直接在主页混排，不再按小说、电影、电视剧分栏或提供类型筛选。推荐语完整展开，评分、看完日期及可访问的关联随笔直接展示；卡片不再跳转独立页。

取消「主页展示」开关与最多 6 部的限制，旧数据中的 `featured` 字段保留兼容但不再控制展示。旧 `/shelf.html` 地址转回 `index.html#stories`，站点地图不再收录独立书架页。后台仍保留类型字段作为作品元数据。

## 原始设计（已由上方展示调整覆盖）

## 1. 定位与范围

在个人网站展示本人愿意推荐、或对自己有影响的电影、电视剧和小说。核心是个人推荐语，让访客理解这些作品为什么被留下。

采用「主页精选 + 独立完整书架」：所有收录条目均属于个人精选收藏，其中一部分额外展示在主页。第一版提供手动录入、封面上传、编辑、删除、排序、类型筛选和随笔关联。

栏目名称：**留下来的故事**。辅助英文标记使用 `STORIES`，延续主页现有 section-tag。说明文字：**看过的故事很多，这些留了下来。**

第一版不加入待看/在看状态、观看进度、自动抓取豆瓣等平台、公开评论、单部作品详情页或私人草稿。初始数据为空，不虚构用户的观影、阅读经历。

## 2. 主页布局

位置在 Photography 与 Listening 之间。顶部导航增加 `Stories`，指向 `#stories`；窄屏同时检查现有导航是否溢出。

```text
STORIES                                  查看全部 →
留下来的故事
看过的故事很多，这些留了下来。

[封面]             [封面]             [封面]
名称               名称               名称
电影 · 导演        电视剧 · 导演      小说 · 作者
个人推荐语……       个人推荐语……       个人推荐语……
```

- 最多展示 6 部，按后台保存的全局顺序选取勾选「主页展示」的作品。
- 桌面三列、中等屏幕两列、手机一列，手机保留足够宽度阅读推荐语。
- 封面统一 2:3 展示框，保留完整图像；不裁掉书名或海报文字，空余处使用主题适配的底色。
- 显示名称、类型、选填的作者/导演、推荐语与「最喜欢」标记。主页推荐语最多显示三行。
- 卡片点击进入完整书架并定位该作品，例如 `shelf.html#story-12`；入口使用真正的链接，支持键盘及新标签页。
- 主页没有勾选的条目时，隐藏该区域及其导航入口；加载失败时也不影响其他栏目。
- 「查看全部」指向 `shelf.html`；完整书架可展示未勾选主页展示的收藏。

## 3. 完整书架

独立页面地址为 `/shelf.html`，标题「留下来的故事 — Chami」。复用现有字体、配色、主题切换及页脚风格，提供返回主页入口。

页面上方展示栏目名称、说明与 `全部 / 电影 / 电视剧 / 小说` 筛选按钮。默认「全部」，按手动顺序展示；筛选保留该顺序。「最喜欢」只作视觉标记，不自动改变排序。

使用与主页一致的封面卡片，但完整显示推荐语。选填的个人评分、看完日期、相关随笔也在这里展示。评分明确标注「我的评分」，采用 1–5 分、允许半分；未填写则不占位。无日期的作品不显示日期。

- 筛选按钮使用原生 button，提供选中状态与结果数量。
- 推荐语支持换行，以纯文本显示；不解析用户输入的 HTML 或 Markdown。
- 有关联随笔时显示「读我的感想 →」。使用现有随笔身份字段关联，只允许选择公开且未加密的文章；文章后来不满足条件时移除链接，并在后台提醒。
- 从主页进入时定位并短暂突出对应卡片；无匹配 ID 时正常显示全部作品。
- 书架为空时显示「还在整理，慢慢把喜欢的故事放进来。」；某类型为空时显示「这个分类还没有收录。」
- 加载失败显示错误与重试入口，封面缺失或加载失败时显示带作品名的占位封面。
- 不新增无限滚动或分页；第一版按个人精选规模实现。

## 4. 数据模型

新增受 Git 跟踪的 `data/stories.json`，顶层为数组，数组顺序即展示顺序。每个条目包含：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 稳定身份 | 后端生成整数，编辑、排序后保持不变 |
| `title` | 作品名称 | 必填，去首尾空白，1–120 字 |
| `type` | 作品类型 | 必填，`movie` / `series` / `novel` |
| `creator` | 导演或作者 | 选填，最多 120 字；电影/电视剧标注导演，小说标注作者 |
| `cover` | 本地封面路径 | 选填，仅允许 `images/stories/` 下合法图片，缺省使用占位封面 |
| `recommendation` | 个人推荐语 | 必填，1–1000 字；表单提示建议写 50–150 字 |
| `favorite` | 最喜欢 | 布尔值，默认 false，公开显示标记 |
| `featured` | 主页展示 | 布尔值，默认 false，全局最多 6 部 |
| `rating` | 我的评分 | 选填，null 或 1–5 的半分步进数值 |
| `finished_on` | 看完日期 | 选填，空值或合法 `YYYY-MM-DD`，不自动补当前日期 |
| `essay_slug` | 关联随笔 | 选填，使用现有随笔 slug，须满足公开且未加密条件 |

数组中的全部字段均可公开访问。后台必须明确提示「保存后可在本地预览；按现有 Git 发布流程发布后公开」。`featured=false` 仅表示不在主页展示，不代表隐藏或私密。

## 5. 管理面板

新增 `Stories 故事` 标签页，使用现有标签页懒加载和表单组件模式。

列表显示缩略图、名称、类型、推荐语摘要、主页展示与最喜欢标记，提供新增、编辑、删除、上移和下移操作。第一版采用按钮排序，同时兼容鼠标、触屏及键盘；排序针对完整列表保存。

编辑表单分为：

1. 基本信息：名称、类型、导演/作者、封面上传与预览。
2. 推荐内容：推荐语、最喜欢、可选评分与看完日期。
3. 展示设置：主页展示、关联随笔选择。

超过 6 部主页精选时拒绝保存并提示先取消其他作品的主页展示，不静默挤掉已有条目。保存失败保留表单内容；删除沿用现有确认交互。删除条目或替换封面时不自动删除图片，避免误删共享资源；未引用封面可由健康检查提示。

上传封面与保存条目分步进行，取消表单可能留下未引用图片。此行为在后台提示，第一版不增加自动清理功能。

## 6. 实现边界与发布

以下为拟新增接口与文件，最终实现需遵循现有模块边界。

- `GET/POST /api/stories`：后台读取、新增。
- `PUT/DELETE /api/stories/<int:id>`：后台编辑、删除。
- `PUT /api/stories/order`：提交完整 ID 序列，拒绝重复、缺失或未知 ID。
- `POST /api/stories/upload-cover`：封面上传，返回本地路径。
- 公开页面读取 `data/stories.json`，不依赖 Flask API 或第三方服务。

后端路由拟放入 `backend/routes/stories.py`，业务校验与排序放入 `backend/story_service.py`，持久化复用现有 `repository_for`、锁和原子写入。主页精选数量限制必须在锁内检查并保存。

前端拟新增 `assets/js/index-stories.js`、`assets/js/shelf.js`、`assets/js/admin-stories.js` 以及对应样式；两处公开展示共享卡片渲染与数据规则，避免主页和书架解释同一字段时产生差异。沿用原生 DOM 和现有全局模块模式。

封面存入 `images/stories/`，复用现有图片类型、大小与 Pillow 真实性校验，使用服务端生成的唯一文件名和原子保存。所有路径规范化后限制在该目录，禁止任意路径及远程 URL。文本转义，保留 session、CSRF 与 Host 校验。

将 `stories.json` 加入 Flask 公开数据白名单，为 `shelf.html` 增加明确的本地预览路由。书架作为受 Git 跟踪的静态 HTML，与现有主页采用相同的数据加载模式。纳入现有 cache bust 处理；站点地图加入书架地址并更新增量生成依赖。GitHub Pages 当前发布仓库构建目录，可沿用现有工作流，不预设需要修改 CI。

健康检查补充数据类型、重复 ID、必填字段、精选数量、封面引用与关联随笔有效性。初始提交仅加入空数组，实际作品及封面由用户提供或在后台录入。

## 7. 实施顺序与验收

设计 review 通过后，按下列顺序实施：

1. 数据模型、业务校验、后台接口与封面上传。
2. 管理面板录入、编辑、排序与精选操作。
3. 主页精选和完整书架、类型筛选与随笔关联。
4. 健康检查、构建和浏览器验证。

验收重点：

- 一部电影、一部电视剧和一部小说可完整录入、编辑和删除；刷新后内容及顺序保持。
- 主页只显示勾选作品，最多 6 部；书架显示全部，筛选结果正确。
- 第 7 部主页精选被明确拒绝；缺封面、缺评分、缺日期时布局正常。
- 推荐语完整展示、特殊字符安全；随笔失效时不留下错误入口。
- 浅色/深色、桌面/手机均可用，键盘可完成筛选和主要操作。
- GitHub Pages 静态环境可访问书架、数据及封面；本地预览行为一致。

实现时运行 `python -m pytest -q`，对每个变更 JS 执行 `node --check`，执行 `python manage.py build` 并检查产物与工作区变化。浏览器验证覆盖后台新增/编辑/排序和公开页面筛选、定位、主题及窄屏布局；运行 `tests/test_browser_smoke.py`，不可把跳过测试视为验证通过。实际发布后的可访问性需另行验证。
